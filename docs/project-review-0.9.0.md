## Проверка результата

104 JS-теста на Node 22 и 24; 10 проверок Python-загрузчика; 2 проверки исторической SQLite; 22 сценария поиска магазинов; 6 браузерных сценариев; lint, typecheck и production build. Общая команда pnpm check проверяется запуском, а не только чтением package.json. Типы маршрутов генерируются перед tsc.

Первый удалённый запуск CI выявил смену ubuntu-latest на Ubuntu 26.04, для которой отсутствует готовый Python 3.9. Runner закреплён на Ubuntu 24.04; наличие обеих версий проверено по официальному versions-manifest actions/python-versions. Окончательный удалённый результат проверяется по странице GitHub Actions.

Браузер проверяет скачивание настоящего файла, очистку и импорт обратно, повторный импорт, отказ повреждённого файла, reload, остановку запросов в скрытой вкладке и offline, возобновление, часы с неправильным годом, 320px и reduced motion. Внешние ответы в этих сценариях изолированы сохранённым HTML.

Резервирование проверяется настоящими файлами и CLI: восстановление исходных дат и условий, ротация, повреждённая копия, неизвестные магазины, частично повреждённый кеш, чужая папка и ошибка переключения с откатом. Отдельно выполнены python3 start.py --backup и --restore из копии проекта без node_modules и сборки. Обычный запуск этой чистой копии устанавливает зависимости и возвращает HTTP 200 на /api/health и главной.

## Внешняя приёмка

Эти пункты требуют конкретного окружения или исходных материалов и сохранены в NEXT_AGENT_TASK.md:

1. Живой сбор ВкусВилла, Магнита и остальных магазинов в доступной сети. Политика текущей среды ограничивает домены магазинов и Bing. Успешные фикстуры не доказывают живую загрузку. Автоматический обход защиты не добавлялся.
2. Физические macOS 12/Safari и Windows: первый запуск, перезапуск, остановка, избранное и файл переноса. Linux проверен; Chromium с отключёнными новыми API не заменяет эти устройства.
3. Оригинал логотипа Крошки Картошки для локального файла. Сейчас используется существующий внешний адрес; при его отказе отображается название. Самодельная эмблема не выдаётся за оригинал.
4. Постоянный сервер, домен и внешнее хранилище: подготовленные systemd/Caddy-конфиги нужно применить на предоставленном сервере и проверить восстановление там. Внешнее резервирование требует хранилища владельца.

Найденный в публикации код может иметь региональные и персональные ограничения. Проверка применения в корзине не входит в нынешний поиск без авторизации. Будущие изменения разметки источников потребуют адаптации парсеров; проект сохраняет ссылки, условия и проверяемые фикстуры для такой работы.
