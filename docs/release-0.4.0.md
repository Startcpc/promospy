# PromoSpy 0.4.0 — избранные промокоды

## Какую проблему решает

Раньше найденный код приходилось искать заново перед заказом, особенно если предложения относились к разным магазинам. Теперь сердечко на карточке сохраняет код, а страница `/saved` собирает избранное в одном месте.

## Новое поведение

- Сохранение и удаление прямо из карточек поиска, магазина и избранного.
- Ссылка «Избранное» со счётчиком на главной и страницах магазинов.
- До 100 кодов в этом браузере, без регистрации. Список сохраняется после перезагрузки страницы и синхронизируется между вкладками того же браузера.
- Поиск по магазину, коду и условиям; фильтр актуальных предложений.
- Условия и статусы загружаются при открытии, по кнопке и каждые 30 секунд. Коды, истёкшие более суток назад, остаются в личном списке с правильным статусом; копирование истёкших отключено. Из общего каталога они по-прежнему скрываются по прежним правилам.
- В браузере хранятся только идентификатор предложения, магазин, код и время сохранения. Статусы и условия не копируются в localStorage и запрашиваются заново с сервера.
- Если предложение удалено из базы, код остаётся в избранном с пояснением и ссылкой на магазин.
- Если сервер недоступен, сохранённые коды остаются видны, а старые подтверждения не показываются. При запрете записи в хранилище браузера отображается ошибка; кнопка не заявляет об успешном сохранении.

Очистка данных сайта или другой браузер создают отдельное избранное. Облачная синхронизация и аккаунты не добавлялись.

## Файлы

- `src/lib/saved-promos.ts`: формат сохранения, проверка содержимого и ограничения.
- `src/hooks/use-saved-promos.ts`: localStorage, подписки и синхронизация вкладок.
- `src/components/save-promo-button.tsx`, `saved-promos-link.tsx`: кнопка и навигация.
- `src/app/saved/page.tsx`: список, фильтры и обновление статусов.
- `src/app/api/promocodes/saved/route.ts`: ограниченный запрос предложений по ID, пересчёт истечения через существующий `toPromoCode`, missingIds, `Cache-Control: no-store`.

Схема Prisma и включённый снимок базы не изменены. Очередь, сроки официального подтверждения и сбор магазинов сохранены.

## Проверки этого этапа

**28 тестов прошли**: 26 доступных unit-проверок и 2 браузерных сценария на production-сборке. Полный ESLint, TypeScript, проверка diff и production-сборка со standalone прошли.

Новый браузерный сценарий проверяет настоящий localStorage и работу интерфейса: пустой список, сохранение со страницы магазина и общего поиска, повторное открытие, поиск по магазину и условиям, обновление до истёкшего статуса, активный фильтр, сбой API без старых подтверждений, исчезнувшее предложение, удаление, синхронизацию вкладок, запрещённое хранилище и мобильную ширину 390 px. Ошибок JavaScript страницы не обнаружено. Недопустимые запросы к настоящему новому API проверены и возвращают 400 без обращения к базе.

Данные успешных ответов API в браузерном сценарии изолированы и основаны на сохранённых официальных HTML-фикстурах. Это проверка новой функции, а не заявление о живом сборе магазинов.

Ограничение окружения осталось: нативный движок Prisma не загружается из-за сетевой политики. Для компиляции использован ранее локально сгенерированный Prisma Client без движка. Полный набор из **42** unit/integration-тестов и `test:smoke` с настоящей Prisma не подтверждены; проверка чтения новым API реальных строк базы также требует штатной генерации клиента. В smoke уже добавлены проверки чтения скрытого/истёкшего сохранённого предложения, missingIds и запрета кеширования. На целевом окружении выполнить обычный `pnpm db:generate`, затем `pnpm test` и `pnpm test:smoke`.

Для браузерной проверки: после сборки `pnpm test:ui`. При использовании системного Chromium можно задать `PROMO_TEST_CHROMIUM_EXECUTABLE=/путь/к/chromium`.
