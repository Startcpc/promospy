# 0.8.2 — исправления после пяти проходов

Владелец отдельно потребовал пять последовательных проверок с исправлениями. Фактические ошибки, результаты до/после и время каждого прохода записаны в [audit-0.8.2-five-passes.md](audit-0.8.2-five-passes.md).

Исправлено:

- Кеш проверяет структуру данных и отбрасывает повреждённые записи до отправки в интерфейс. Частично повреждённый кеш и незавершённый результат после рестарта не запрещают повторный поиск.
- Прерванный поиск не продлевает время успешного обновления, если были прочитаны только индексные страницы. Health проверяет возможность записи, а не только существование папки.
- Непрочитанные источники сохраняются по отдельности: исчезновение кода на одном сайте не уничтожает прошлое наблюдение с другого недоступного сайта. Сохранённые результаты ограничены 100 кодами, свежие имеют приоритет.
- Ошибка записи кеша больше не теряет найденные коды: они доступны в памяти до перезапуска с явным предупреждением. Старое успешное время дискового кеша сохраняется.
- Видимая карточка и признаки архивной акции имеют приоритет над старой JSON-копией. Это исправляет неверное отображение завершённых кампаний и повторно использованных кодов. Совпадающие метаданные со сроками сохраняются.
- Поиск исключает повторные адреса с фрагментами и UTM, слишком длинные URL, скрытые сообщения о пустом списке и пустые списки другого магазина. Кириллица читается с учётом charset страницы, включая Windows-1251.
- Избранное сохраняет минимальный заказ, начало акции и реальное время наблюдения источника. Длинные Unicode-ID загружаются короткими пакетами; восстановление localStorage возвращает синхронизацию вкладок.
- Повторное копирование корректно перезапускает уведомление. Запоздавшая ошибка предыдущей попытки не портит новый успешный результат.
- Неверные адреса магазина показывают русскую страницу 404. Сетевой сбой API не маскируется отсутствием промокодов.
- Загрузчик восстанавливается после повреждения state.json, записывает состояние атомарно, проверяет Node/npm и учитывает платформу, путь проекта и конфигурацию установки. При переносе переустанавливает нативные зависимости.
- Кеши npm/pnpm размещаются в папке проекта. Проверка и резервирование порта происходят до установки/сборки; немедленный повторный запуск после остановки на POSIX больше не блокируется TIME_WAIT.
- Production-копирование очищает удалённые статические файлы. Команды исторической SQLite-копии работают без обязательного .env и правильно разрешают пути независимо от текущей папки.

Проверено на Linux: 81 JS-тест на Node 22 и Node 24, 8 проверок Python-загрузчика, 2 SQLite-проверки, 22 сценария поиска магазинов, 3 браузерных сценария, lint, typecheck и production build. pnpm audit --prod не сообщил известных уязвимостей. Исходная база сохранена без изменений; runtime-зависимостей осталось 6.

Дополнительно выполнен настоящий первый запуск из чистой папки без установленного Node/pnpm, зависимостей, сборки и .git: загрузчик подготовил окружение и сервер вернул HTTP 200. Повторный подготовленный запуск занял около 0,5 с в этом окружении. Затем проверен настоящий перенос подготовленной папки в путь с пробелами, переустановка, сборка и повторный запуск. Эти измерения не являются обещанием скорости другого компьютера.

Браузерные источники изолированы сохранённым HTML. Прямой живой сбор с магазинов по-прежнему ограничен сетевой политикой среды; доступность сайтов и применение каждого кода к корзине этими тестами не подтверждаются. Нативные проверки на физических macOS 12 и Windows остаются в NEXT_AGENT_TASK.md.

Запуск для владельца прежний: python3 start.py на Mac/Linux либо START_WINDOWS.cmd на Windows. Дополнительные ручные настройки для обычного запуска не требуются; первый запуск требует доступа к nodejs.org и registry.npmjs.org.
