# 0.8.3 — повторная проверка ошибок

Продолжение после пяти проходов 0.8.2 по новому требованию владельца. До исправлений семь новых unit-сценариев воспроизвели ошибки, затем дополнительный сценарий выявил неверные даты JSON. Браузер отдельно воспроизвёл отсутствие обновления после TTL и отказ поиска без новых методов AbortSignal. Сохранённые HTML и искусственные сбои используются только в тестах.

Исправлены следующие проблемы:

- Открытая страница после истечения 15-минутного кеша запускает новый поиск. Один опрос GET больше не оставляет страницу со старыми данными навсегда. Повтор после ошибки ручного обновления сохраняет refresh=1.
- Сбой официального сайта сохраняет последнее подтверждение и его исходное время, даже когда сторонний источник публикует тот же код с другими условиями. Успешное подтверждение исчезновения по-прежнему снимает официальный статус.
- Ошибка разбора распознанной официальной карточки больше не запускает общий fallback. Старый JSON не может обойти отклонённые условия и выдать акцию без срока.
- Официальные карточки общего формата сохраняют обе границы явно указанного периода. Исправлена склейка текста кода с началом соседнего абзаца.
- Некорректные и перевёрнутые явные даты в JSON и атрибутах не превращаются в бессрочные предложения. Повреждённые даты за пределами календарного диапазона отбрасываются до интерфейса.
- Сохранённая копия истёкшей или отклонённой акции сохраняет свой отрицательный статус при потере серверного кеша; положительные заявления official/verified по-прежнему не сохраняются как подтверждение.
- Запросы в браузере используют обычный AbortController с очисткой таймеров. Для поиска и избранного не требуются новые AbortSignal.any, timeout и throwIfAborted. При отказе одного пакета избранного остальные незавершённые запросы отменяются.
- В package.json явно указан формат ES modules, что устраняет предупреждение Node о повторном определении типа модулей.

Итоговая проверка: 92 JS-теста на Node 22 и 24; 8 Python-проверок; 2 SQLite-проверки; 22 сценария поиска магазинов; 5 браузерных сценариев; lint, typecheck и production build. Браузер проверяет автоматическое обновление с управляемыми часами, повтор ручного запроса, отмену пакетов избранного и работу с отключёнными новыми методами AbortSignal. В этих проверках не осталось падений. Повторный pnpm audit --prod сообщил 0 известных уязвимостей.

Физические macOS 12/Safari и Windows здесь отсутствуют. Тест совместимости выполняется в Chromium с отключением соответствующих API. Прямой сбор с сайтов магазинов по-прежнему ограничен сетью среды; тестовые ответы не подтверждают живой сбор или успешное применение промокода в корзине. Абсолютное отсутствие неизвестных ошибок не утверждается.

Первый запуск и перенос папки отдельно проверены в 0.8.2; загрузчик в 0.8.3 не менялся. Его 8 регрессий выполнены повторно. Исходная SQLite и Prisma-схема не изменены. Запуск для владельца: python3 start.py.
