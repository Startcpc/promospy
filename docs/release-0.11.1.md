# PromoSpy 0.11.1 — живой сбор и GetCashback

08.11.2026 проверен актуальный main `618baf9` и его успешный GitHub Actions. В подключённой Linux-среде Node 24.22.1, pnpm 11.25.0, Python 3.12.14 и системный Chromium. Сетевой режим unrestricted/enforced; настоящий HTTPS из приложения работает через унаследованный прокси с проверкой TLS. Прежнее ограничение «0 прочитанных страниц» здесь не воспроизводится.

## Воспроизведённый дефект и исправление

GetCashback отвечал HTTP 200 и отдавал полное значение `.promo-num`, заголовок `.stock-info > p.promokode-modal`, срок `.remain` и условия `.coupon-details`. Общий парсер ожидал другие классы и заголовки: все три страницы давали 0 кодов.

Добавлен адаптер только для getcashback.ru, который приводит эту разметку к общему парсеру карточек. Он не открывает popup/referral URL и не выполняет скрипты. Сохраняются сроки по Москве, минимум заказа, ограничения и архивный статус. «Похожие купоны» на этом сайте — обычный div `.coupon-title`, а не h2: весь последующий блок исключается, чтобы чужие магазины с такой же разметкой не попадали в выдачу. Маски, рекламный TG-баннер, скрытые и платные карточки не извлекаются.

Наблюдавшиеся документы GetCashback после исправления: Burger King — 25 архивных предложений, без активных; ВкусВилл — 25 предложений, 8 неистёкших; Магнит — 36 предложений, 11 неистёкших. Это результаты отдельных страниц до объединения с другими источниками, не число уникальных кодов всего поиска. У Burger King действующий найденный код поступает с другого источника.

ENGINE_VERSION поднят до 6: старый кеш обновится обычным поиском. Формат кеша, SQLite, Prisma, избранное и резервные копии не менялись. Синтетические значения из регрессионной фикстуры не загружаются приложением.

## Прямая проверка каталога

Проверены все 61 известный адрес из 20 сторонних каталогов, а также 6 официальных URL Burger King / ВкусВилла / Магнита. Сохранены реальные тела успешно загруженных документов и robots.txt, HTTP, конечный URL, время и ошибки в `work/source-audit/`. Это отдельные диагностические файлы, не кеш приложения; они не коммитятся.

Из 61 адреса загружены 52; 9 не прочитаны: 5 ошибок robots.txt (Mail.ru и 7days), 2 HTTP 403 (Промокоди.net и Промокодофф), 2 HTTP 404 (Okodo ВкусВилл и КП Яндекс Маркет). Официальный Burger King дал HTTP 403; официальные ВкусВилл и Магнит отдали настоящие коды. Доступная страница сама по себе не означает наличие полного публичного кода или успешный разбор. Fontanka и часть Promocodex имеют неоднозначные/неполные даты; эти записи продолжают отклоняться. Маски ПромКода и Технопанорамы не выдаются за полные коды.

Добавлена воспроизводимая команда:

```sh
pnpm audit:sources          # все каталоги и официальные URL
pnpm audit:sources 5 54 201 # только выбранные магазины
```

Каждый запуск пишет в новый `work/source-audit-<UTC timestamp>/`: `summary.json`, `<n>.body` и `<n>.json` с метаданными. Действуют тот же PublicHttpClient, robots, разрешённые домены, TLS, ограничения размера, очереди и повторы. Три параллельных задания не отменяют ограничения клиента на один хост. Ошибка одного адреса не прекращает аудит. Команда проверена на Burger King.

`pnpm test:live` теперь отдельно считает неистёкшие/начавшиеся и остальные предложения, выводит условия и диагностику индексов, закрывает HTTP-dispatchers. Только архивные записи больше не дают успешный итоговый код возврата.
