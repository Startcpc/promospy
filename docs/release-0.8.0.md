# 0.8.0 — автоматическая загрузка

При открытии магазина поиск запускается сам. Главная и предзагрузка ссылок читают только локальное состояние: внешний обход всего каталога не запускается. Сохранённые результаты приходят вместе с HTML страницы; свежие добавляются по мере чтения. Кнопка «Обновить» принудительно запускает новый поиск без ожидания 15 минут. Одновременные запросы объединяются, лишние магазины автоматически ждут в очереди с двумя исполнителями.

Первый этап — официальный сайт. Для ВкусВилла используется `/promocodes/`, для Магнита — `promo.magnit.ru`; восстановлены чистые парсеры опубликованных карточек с условиями. Затем читаются ссылки акций с официального сайта. Лишь после этого запускаются сторонние источники. Их известные адреса читаются одновременно с поисковой выдачей, без ожидания RSS. Официальные коды получают статус публикации с датой, а не проверки корзины. Условия официальной карточки имеют приоритет при совпадении кода.

Сбой одного источника не прерывает остальные. Детали находятся в раскрываемом блоке; на экране остаются результаты и спокойное сообщение о повторе. Нулевое число прочитанных страниц не считается успешным обновлением и не стирает кеш. После сбоя клиент повторяет поиск автоматически. Источники, которые не удалось прочитать заново, не обновляют подтверждение старых кодов. Технические ошибки сохранения и Origin продолжают обрабатываться явно.

Устранена зависимость видимости логотипа от события onLoad после гидратации: изображения показываются браузером сразу. Убраны квадратные буквенные заглушки. Двенадцать логотипов находятся в public/logos; Крошка Картошка пока использует прежний внешний оригинал, а при ошибке выводится полное название. Включена предзагрузка страниц, добавлен loading.tsx. Нажатия не ждут анимации, touch-action: manipulation убирает задержку двойного касания.

Учтён HTTPS_PROXY через штатный Node http.setGlobalProxyFromEnv при наличии этого API. При работе через прокси имена разрешает сам прокси: лишняя локальная DNS-проверка больше не ломает загрузку в среде без прямого DNS. NO_PROXY учитывается. Прокси и доверенные сертификаты среды не обходятся. В этой среде действующая сетевая политика не разрешает сайты магазинов или Bing, поэтому успешный живой сбор не заявляется.

Проверки: 41 unit-тест, 22 сценария поиска магазинов, браузерный сценарий с настоящими API/кешем/избранным и изолированными внешними источниками, lint, typecheck, production build. Браузер проверяет автоматический POST, ручное обновление, отсутствие поиска на главной и видимость 12 локальных логотипов с отключённым JavaScript. Для Node 24.22 тестовые команды используют --experimental-test-isolation=none, чтобы resolver hook не превращал отчёт в фиктивное прохождение файлов вместо отдельных тестов.

Локальный запуск: python start.py или START_WINDOWS.cmd. При отсутствии Node.js загрузчик использует официальный архив Node 22 LTS с nodejs.org с SHA-256, распаковывает его только в .runtime, затем готовит зависимости и production-сборку. Готовые зависимости/сборка повторно используются по отпечатку файлов. GitHub не участвует в работе приложения; Codespaces остаётся необязательным вариантом. Python нужен только загрузчику, сервер выполняется переносимым Node.js.

Проверка локального загрузчика на Linux: официальный Node v22.23.4 скачан с проверкой SHA-256, переносимый npm запускается. Локальный production-сервер стартовал через start.py на переносимом Node с уже подготовленными зависимостями и сборкой, /api/health вернул HTTP 200. Чистая установка на Windows ещё не проверена и указана в задании следующему агенту.

Очистка проекта: 64 прямые runtime-зависимости сокращены до 6. Удалены неиспользуемые shadcn-компоненты и тостер, старые WebSocket-примеры, генераторы логотипов, прежние сборщики и 70 лишних изображений. 12 используемых локальных логотипов и исходная база сохранены. Нужные HTML-фикстуры лежат в tests/fixtures. На Mac предусмотрен START_MAC.command; Node 22 имеет официальный минимум macOS 11, поэтому подходит для macOS 12 на Intel и ARM. Проверка на физическом Mac ещё требуется.
