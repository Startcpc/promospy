# Пять проходов проверки — 0.8.2

Начаты после отдельного требования владельца выполнить пять последовательных проходов. Фиксируются фактические результаты, включая воспроизведённые ошибки.

## 1. Кеш и сохранение источников — 07.11.2026 17:09 МСК

До исправления два новых сценария упали: успешное исчезновение кода на одном сайте удаляло копию с другого недоступного сайта; частично повреждённый свежий кеш запрещал повторный поиск на 15 минут. Исправлено сохранение непрочитанных источников по отдельности и принудительное обновление повреждённого кеша.

Повтор: 17 тестов search-store прошли, typecheck прошёл.

## 2. Карточки и сроки — 07.11.2026 17:11 МСК

Два новых сценария воспроизвели дублирование и неверный приоритет JSON-копии над видимой карточкой: завершённая акция могла оказаться активной, а новая акция с повторно использованным кодом — истёкшей. Исправлен приоритет карточки; сроки из JSON переносятся только при совпадении кода и описания.

Повтор: 55 тестов разбора и веб-поиска прошли, typecheck прошёл.

## 3. Браузер и повторные нажатия — 07.11.2026 17:14 МСК

Новый браузерный сценарий сначала упал: запоздавшая ошибка первого копирования портила состояние второго успешного нажатия. Исправлен приоритет последней попытки и перезапуск двухсекундного сообщения.

Повтор: production build прошёл; 3 браузерных сценария прошли, включая таймер копирования, избранное между вкладками, восстановление localStorage, 100 длинных Unicode-ID и 404.

## 4. Настоящий запуск и перенос папки — 07.11.2026 17:19 МСК

Реальный повторный запуск после остановки сначала упал с ложным «порт занят» из-за TIME_WAIT. Исправлено резервирование порта: POSIX SO_REUSEADDR и listen на время подготовки, с сохранением Windows SO_EXCLUSIVEADDRUSE. Добавлена отдельная регрессия немедленного перезапуска.

Повтор: 8 Python-проверок прошли. Настоящий загрузчик запущен из /tmp/promospy-clean-launch-082, затем папка переименована в /tmp/PromoSpy audit folder 082 и запуск повторён. В обоих случаях /api/health и главная вернули HTTP 200; путь проекта записан корректно. Проверка включает принудительную переустановку при переносе и production-сборку; отпечатки вручную не подставлялись.

## 5. Итоговая регрессия и повтор после последнего исправления — 07.11.2026 17:29 МСК

Полный набор сначала прошёл, затем дополнительная проверка отказа записи выявила потерю свежих кодов при ошибке сохранения кеша. Сценарий воспроизведён падением теста. Исправлено: свежие результаты остаются в памяти с предупреждением, при этом успешное время дискового кеша не подменяется и сведения об источниках не обновляются искусственно.

После этого исправления весь итоговый набор выполнен заново: lint и typecheck прошли; 81 JS-тест прошёл на Node 22 и повторно на Node 24; 8 Python-проверок прошли; 2 SQLite-проверки прошли; 22 сценария поиска магазинов прошли; production build прошёл; все 3 браузерных сценария прошли. pnpm audit --prod сообщил 0 известных уязвимостей. Исходная база и Prisma-схема не изменены.

## Границы результата

Пять проходов завершены последовательно. Первые четыре сосредоточены на отдельных подсистемах с воспроизведением найденных ошибок; пятый — на полной регрессии и повторе после последнего исправления. Это не пять одинаковых запусков одного теста.

Нативная среда проверки — Linux. Переносимые бинарники и сборка проверены на Node 22, тесты — также на Node 24. Физические Mac и Windows здесь отсутствуют. В браузерных проверках ответы внешних источников изолированы сохранённым HTML; успешное применение промокодов в корзине не заявляется. Сетевая политика среды по-прежнему ограничивает прямой живой сбор с магазинов.
