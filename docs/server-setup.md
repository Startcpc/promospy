# Сервер PromoSpy

Один долгоживущий Node.js 22.18+ процесс. Выполнить pnpm install --frozen-lockfile, pnpm build, затем pnpm start. Системный браузер, аккаунты, API-ключи и Prisma для приложения не требуются.

Задать PROMO_SEARCH_DATA_DIR абсолютным путём на постоянном диске, например /var/lib/promospy/search. Для копий задать PROMO_SEARCH_BACKUP_DIR=/var/lib/promospy/backups. Пользователь сервиса должен иметь доступ к этим каталогам на запись. По умолчанию используются .cache/promo-search и .cache/search-backups в проекте.

## Настройка на Linux

Файлы в deploy/systemd и deploy/Caddyfile подготовлены как шаблоны. Для действующего сайта нужны собственный сервер, домен и доступ к источникам; в этой сессии они не предоставлены, поэтому развёртывание не выполнялось.

1. Разместить проект в /opt/promospy, подготовить зависимости и production-сборку. Установить Node 22.18+ по /usr/bin/node либо исправить путь в service-файлах.
2. Создать системного пользователя promospy и каталог /var/lib/promospy с владельцем promospy:promospy. Пользователю достаточно читать /opt/promospy; runtime-запись идёт в /var/lib/promospy.
3. Скопировать deploy/promospy.env.example в /etc/promospy.env, указать пути и при необходимости PROMO_PUBLIC_ORIGIN. Скопировать promospy.service, promospy-backup.service и promospy-backup.timer из deploy/systemd в /etc/systemd/system.
4. Выполнить systemctl daemon-reload, systemctl enable --now promospy.service, затем открыть /api/health через настроенный домен.
5. После появления результатов выполнить systemctl start promospy-backup.service и проверить journalctl -u promospy-backup.service. Затем systemctl enable --now promospy-backup.timer. Копирование выполняется ежедневно с сохранением 7 последних копий. Список: systemctl list-timers promospy-backup.timer.
6. Настроить Caddy под свой домен и DNS. Приложение слушает 127.0.0.1:3000; публичный TLS обслуживает Caddy.

## Копирование и восстановление

Ручная копия: pnpm cache:backup. Альтернатива для локального запуска: python3 start.py --backup. Запущенный сайт можно продолжать использовать во время чтения атомарных файлов кеша; каждый магазин копируется отдельно, общего снимка одновременно работающих поисков нет.

Перед восстановлением на сервере остановить promospy-backup.timer и promospy.service. Выполнить pnpm cache:restore /абсолютный/путь/к/копии.json от пользователя promospy с тем же EnvironmentFile. В обычном терминале задать те же PROMO_SEARCH_DATA_DIR и PROMO_SEARCH_BACKUP_DIR; systemd не экспортирует их автоматически в shell.

Весь файл проверяется до замены. Результаты сначала записываются в подготовленную папку. Прежний каталог сохраняется рядом как search.before-restore-UUID. При ошибке переключения выполняется возврат прежнего каталога. Для восстановления требуется возможность переименования каталогов в родительской папке; разместить search внутри постоянного диска, а не делать сам search точкой монтирования. Исходные даты публикации и проверки не обновляются искусственно.

После восстановления запустить promospy.service, проверить /api/health и страницу магазина, затем снова включить promospy-backup.timer. Если потребуется ручной откат, при остановленном сервисе сохранить восстановленный каталог отдельно и вернуть прежнюю папку по исходному пути. Автоматически старые папки before-restore не удаляются.

Копии на том же диске защищают от повреждения файлов. Для отказа всего диска дополнительно настроить перенос PROMO_SEARCH_BACKUP_DIR на собственный внешний носитель или удалённое хранилище. Учётные данные для этого в проект не включаются.

Избранное хранится в браузере посетителя; его перенос выполняется отдельным JSON-файлом на странице «Избранное». Историческая db/custom.db сохраняется отдельно. Старые команды db:backup и db:restore относятся только к ней и не резервируют нынешнюю выдачу.

/api/health проверяет возможность записи в кеш. HTTP 200 не подтверждает доступность магазинов. Исходящему HTTPS нужны Bing и домены из src/lib/web-search.ts. Защита сайта или запрет сети даёт частичный результат с сохранением прошлых наблюдений; ограничения не обходятся. Незавершённый поиск после рестарта можно запросить заново.
