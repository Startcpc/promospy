# PromoSpy 0.10.3 — отказы источников и устаревшая сборка

## Конкретный запрос пользователя

Пользователь запускает клон репозитория в VS Code. В присланном логе Burger King: две страницы burgerkingrus.ru возвращают 403, Пикабу — 404, promokodus.com — проверку браузера, прочитана одна страница. Упомянутый сначала 401 в присланном логе не присутствует. Сообщение «Открытых промокодов пока не найдено. Можно посмотреть акции на сайте магазина» отсутствует в текущем интерфейсе; его удаление есть в истории Git. Поэтому кроме ошибок источников необходимо обновить и пересобрать фактически запущенный клон.

## Исправления

- 401/403 одного URL больше не открывает 15-минутную блокировку всего хоста. Закрытый адрес остаётся закрытым и не запрашивается повторно в течение паузы; другие публичные адреса и независимые источники проверяются. 429 с Retry-After по-прежнему приостанавливает хост.
- Для robots.txt отдельно обрабатываются успешный пустой 200/204 и unavailable-ответы 400/401/403/404/405/410. Такие ответы не считаются правилом Disallow для всех документов. Это соответствует разрешённой обработке unavailable в [RFC 9309 §2.3.1.3](https://www.rfc-editor.org/rfc/rfc9309.html#section-2.3.1.3). Прямой 401/403 страницы не превращается в успех. Сетевые ошибки, 429/5xx, нераспознанный challenge и явный Disallow не дают разрешения. Авторизация, смена личности, решение CAPTCHA и обход сетевой политики не добавлялись.
- Ошибка загрузки robots.txt сохраняет настоящий URL этого файла и фактическое число попыток. Раньше она могла указывать на страницу акции и терять данные попыток.
- Burger King получает ещё два известных публичных адреса в разрешённых доменах: getcashback.ru/promocodes/burgerking/ и promokod.vbr.ru/shops/burger-king/. Существующие источники сохранены. Пикабу использует /shops/burgerkingrus, а не прежний /shops/burger-king. Никаких значений промокодов в реестр не добавлено.
- Исправлена воспроизводимая гонка чтения: поиск мог завершиться между чтением старого файла кеша и чтением статуса задания. Ответ ошибочно сочетал idle и прежние предложения. Согласованность проверяется по ревизии конкретного магазина; при изменении чтение повторяется.
- /api/health и «Подробнее об обновлении» показывают версию реально собранного приложения. Отказы страниц объяснены словами, рядом остаётся HTTP-код и ссылка на фактически проблемный адрес. Ошибки не скрываются.
- Раздел «Купоны ... доступные ранее» распознаётся как архив. Даже будущая дата в карточке не превращает такую публикацию в действующую акцию.
- ENGINE_VERSION=4 инициирует новое чтение старого кеша; существующие данные и избранное не очищаются.

## Проверки

Новые HTTP-сценарии сначала дали 9 ошибок из 13 до исправлений; два дополнительных проверяют поиск через другой официальный URL и через резервный источник Burger King. Отдельно воспроизведён возврат старого кеша после завершения поиска и исправлен.

Итоговый набор — 214 JS-тестов, 9 браузерных сценариев, 12 Python, 2 теста SQLite-инструментов и 22 проверки поиска каталога; lint, TypeScript и production-сборка. Новый сценарий интерфейса воспроизводит robot 401, официальный 403, сторонний 404 и challenge, затем проверяет появление предложения из публичного резервного ответа, ручное повторное чтение и избранное. Это изолированные синтетические ответы, не доказательство живого сбора или действительного применения купона. Они не импортируются приложением и не записываются в рабочую выдачу.

Исследовательский веб-инструмент открыл актуальный Пикабу-адрес Burger King и страницу promokodi.ru/store/burger-king/, а также нашёл два дополнительных публичных адреса. Сами страницы содержат акции, скрытые/архивные предложения и условия; это не обещание наличия открытого действующего кода. Поисковые сниппеты не используются как рабочая выдача.

Новый живой scripts/test-live.ts 5 здесь дал 0 прочитанных страниц: текущая restricted-сеть блокирует источники. Изменение обработки HTTP-ответов robots.txt не обходит эту транспортную блокировку. Успех у пользователя и применение кодов в корзине пока не заявляются. Исходные db/custom.db и Prisma-схема сохранены.

## Обновление клона

Остановить прежний сервер Ctrl+C в его терминале. В папке своего клона:

```sh
git pull --ff-only origin main
python3 start.py
```

На Windows вместо python3 использовать python. Launcher сам установит изменившиеся зависимости и пересоберёт изменённые исходники. Если обычно используется pnpm start, сначала выполнить pnpm install --frozen-lockfile и pnpm build — один git pull не обновляет уже собранную .next.

В «Подробнее об обновлении» должно быть PromoSpy 0.10.3; в /api/health — version 0.10.3. Если версия другая, открыт другой процесс/проект или прежняя сборка. При отказах источников сохранить полный URL и HTTP-код конкретной строки. Обновление Git применяется только при получении новой версии; работа приложения по-прежнему не требует GitHub.
