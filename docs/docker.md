# Запуск PromoSpy через Docker

На Windows/macOS установите и запустите Docker Desktop; на Windows используйте Linux containers / WSL 2. На Linux нужен Docker Engine. Для Docker-запуска Python, Node.js и pnpm на компьютере не нужны.

## Готовый образ: одна команда

```sh
docker run -d --name promospy --init --platform linux/amd64 -p 127.0.0.1:3000:3000 -v promospy-data:/app/data --restart unless-stopped rashid1501/promospy:0.15.0
```

Откройте **http://localhost:3000** → «Промокоды ВкусВилл» → **«Обновить»**. Git и сборка не нужны. Docker автоматически скачает образ. Поддерживаемая архитектура образа — `linux/amd64`; Apple Silicon запускает его через эмуляцию Docker Desktop. Тег `0.15.0` закрепляет версию, `latest` указывает на последнюю опубликованную.

Если имя `promospy` уже занято, проверьте `docker ps -a`: существующий контейнер запускается через `docker start promospy`. Если порт занят, замените `127.0.0.1:3000:3000` на `127.0.0.1:3001:3000` и откройте http://localhost:3001.

```sh
docker logs -f --tail=100 promospy
docker exec promospy node scripts/test-container.mjs
docker exec promospy node scripts/test-container.mjs --live
docker stop promospy
docker start promospy
```

Для обновления готового образа остановите и удалите только контейнер, затем запустите его заново с тем же томом:

```sh
docker pull rashid1501/promospy:latest
docker stop promospy
docker rm promospy
docker run -d --name promospy --init --platform linux/amd64 -p 127.0.0.1:3000:3000 -v promospy-data:/app/data --restart unless-stopped rashid1501/promospy:latest
```

Том `promospy-data` сохраняется при удалении контейнера. Избранное хранится в браузере. Не удаляйте том, если хотите сохранить кеш. Проверки `healthy` и `--live`, сетевые ограничения и настройка корпоративного CA описаны ниже; они относятся и к готовому образу.

## Сборка из репозитория

Для этого варианта дополнительно нужны Git и Docker Compose v2.

Проверка среды:

```sh
docker version
docker compose version
```

Если приложение уже запущено через `python start.py`, сначала остановите его сочетанием Ctrl+C, чтобы освободить порт 3000. Первый запуск Docker:

```sh
git clone --branch main https://github.com/Startcpc/promospy.git
cd promospy
docker compose up -d --build --wait
```

Если проект уже скачан, выполняйте команды из его папки. Первый запуск требует интернет и время на сборку. Откройте **http://localhost:3000** → «Промокоды ВкусВилл» → **«Обновить»**. До нажатия кодов нет; после него поступают результаты свежего чтения. Далее сервер обновляет их каждые 5 минут, пока контейнер запущен.

Статус, логи и проверка приложения:

```sh
docker compose ps
docker compose logs -f --tail=100
docker compose exec -T promospy node scripts/test-container.mjs
```

Ctrl+C прекращает просмотр логов и не останавливает контейнер. `/api/health` и статус `healthy` проверяют само приложение и запись кеша, а не доступность внешних сайтов. Для настоящего поиска без браузера:

```sh
docker compose exec -T promospy node scripts/test-container.mjs --live
```

Команда действительно читает публичные источники и выводит число неистёкших предложений и статусы источников. При нуле предложений она завершается с ошибкой. Это проверка публикаций, не применения в корзине. Авторизация и покупки не выполняются.

Обновление проекта и образа:

```sh
git pull --ff-only origin main
docker compose up -d --build --wait
```

Перезапуск и остановка:

```sh
docker compose restart
docker compose stop
docker compose start --wait
```

Результаты находятся в именованном томе `promo-data` (`/app/data/search` внутри контейнера). Обычные `up`, `restart`, `stop` и `docker compose down` сохраняют том. **Не используйте `docker compose down -v`, если хотите сохранить результаты.** Избранное хранится в браузере; экспортируйте его через «Избранное → Перенос избранного».

Если порт 3000 занят, создайте в папке проекта `.env` со строкой `PROMO_PORT=3001`, затем снова выполните `docker compose up -d --wait`. Адрес будет **http://localhost:3001**. Внешний порт меняется, внутри контейнера остаётся 3000. `.env` не включается в образ.

По умолчанию порт доступен только с этого компьютера (`127.0.0.1`). Для публичного сервера используйте reverse proxy и HTTPS: [server-setup.md](server-setup.md). Compose запускает один Node-процесс; несколько реплик без отдельной координации не поддерживаются.

## Если источники не читаются

Посмотрите текущий отчёт после «Обновить» либо вывод `--live`. Ошибка отдельного источника не останавливает остальные. CAPTCHA, HTTP 401/403/429 и запреты robots.txt соблюдаются. VPN и общие IP могут влиять на доступность; успешное чтение на другом компьютере не гарантирует доступ в вашей сети.

Docker использует собственную сеть. При корпоративном HTTPS-прокси настройте прокси Docker и доверенный CA своей организации. Для такого окружения подготовлен дополнительный `compose.ca.yaml`: он передаёт CA в сборку через BuildKit secret, а в запущенный контейнер — через read-only mount. Укажите полный путь к доверенному сертификату.

PowerShell:

```powershell
$env:PROMO_CA_FILE = 'C:\certificates\company-ca.pem'
docker compose -f compose.yaml -f compose.ca.yaml up -d --build --wait
```

Linux/macOS:

```sh
export PROMO_CA_FILE=/путь/к/ca.pem
docker compose -f compose.yaml -f compose.ca.yaml up -d --build --wait
```

В этой конфигурации используйте оба `-f` и для последующих команд, например `docker compose -f compose.yaml -f compose.ca.yaml logs -f --tail=100`. Параметры `HTTPS_PROXY` / `NO_PROXY` задаются в настройках Docker или собственном runtime override; адрес прокси должен быть доступен из контейнера. Сертификат не сохраняется в слоях образа. Проверка TLS остаётся включённой.

Образ запускается пользователем `node`, содержит production-сборку и не включает пользовательский `.env`, локальный кеш, Git, Python, тестовые фикстуры или установленные на хосте зависимости. Дополнительный браузер и платные сервисы для обычного поиска не требуются.

## Фактически проверено

14 ноября 2026 года, версия **0.15.0**: образ `linux/amd64` собран на Docker Engine 29.9.2 с драйвером `vfs` в среде с диском 8 ГБ. Dockerfile устанавливает зависимости, собирает приложение и удаляет временные файлы в одном слое, затем переносит только production-артефакты в runtime. Контейнер работает пользователем `node`, получает статус `healthy` и сохраняет кеш побайтно после полного пересоздания. Локальные исходники, `.env`, Git, тесты и секрет сборки в runtime отсутствуют.

Реальный поиск из контейнера прочитал 9 страниц: 36 неистёкших предложений, 63 записи вместе с архивом. Все 9 прочитанных страниц и 7 основных URL отдельного source-аудита вернули HTTP 200; 63 извлечённые записи сверены с полными значениями и датами в исходных публикациях. Chromium проверил пустую страницу без запросов поиска до клика, обновление, копирование, избранное после reload и offline, архив и мобильную вёрстку. Ошибок JS, console и неожиданных HTTP-ошибок не было. Полный `pnpm check` и `pnpm audit --prod` прошли. Это результаты указанной даты и сети, без проверки применения в корзине.

13 ноября 2026 года: Docker Engine 29.9.2, Compose 2.40.3, Node 22.23.5 внутри образа. Образ собран, контейнер запущен без root и получил статус healthy. Настоящий поиск из контейнера прочитал 9 страниц и нашёл 36 неистёкших предложений, всего 63 записи с архивом; значения и извлечённые даты сверены с публичными источниками. Все 7 URL source-аудита вернули HTTP 200. Это результаты этой сети и даты, а не гарантия будущей доступности или применения в корзине.

После полного пересоздания контейнера кеш сохранился побайтно. Chromium через опубликованный порт проверил пустую страницу до клика, отсутствие запросов поиска до «Обновить», ручной поиск и обновление, clipboard, избранное после reload и offline, архив и мобильные размеры. Неожиданных HTTP-ошибок, ошибок console и исключений JS не было. Полный `pnpm check` прошёл: 263 unit-теста, 25 проверок поиска, 12 тестов Python-лаунчера, сборка и 9 Chromium-тестов. `pnpm audit --prod` не нашёл известных уязвимостей.

Дополнительный вариант `compose.ca.yaml` также реально собран и запущен в среде с HTTPS-прокси: проверка `--live` прошла с включённым TLS. В обычной сети используется только `compose.yaml`.
