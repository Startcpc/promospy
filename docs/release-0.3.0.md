# PromoSpy 0.3.0 — изменения и проверки

Дата: 5 ноября 2026, московское время. Обновление существующего проекта; интерфейс компактных карточек, история, очередь и правила официального статуса сохранены.

## Исправлено

- Ошибка загрузки больше не переносит дату последнего успешного официального мониторинга. Текст ошибки виден и при отсутствии первой успешной проверки.
- Фильтр «Только актуальные» исключает акции, которые ещё не начались. Это работает в общем серверном поиске до пагинации и в клиентском фильтре магазина. Сам факт официальной публикации будущей акции сохраняется; в условиях видно, что акция ещё не началась.
- Burger King направляет на российский `burgerkingrus.ru`, вместо американского `bk.com`. Это исправление адреса, а не заявление о готовом новом адаптере.
- Шрифты Geist включены локально вместе с лицензией. Production-сборка не требует обращения к Google Fonts.
- Из локального Caddyfile удалена возможность задавать произвольный порт прокси через параметр запроса. Для production добавлен отдельный конфиг с доменом.
- В pnpm 11 явно разрешены необходимые сборочные скрипты зависимостей; версия менеджера закреплена в package.json.

## Условия и сроки

Официальные адаптеры поддерживают:

- полные даты `5.11.2026`, `05.11.2026`, `5 ноября 2026`;
- диапазоны `с 1.11 по 30.11.2026`, `с 1 по 30 ноября 2026`, `с 1 ноября по 30 ноября 2026`;
- время после даты с явной отметкой МСК, например `до 5 ноября 2026 в 18:30 МСК`;
- денежные скидки и минимальный заказ с пробелами и копейками; отдельные карточки Магнита могут содержать денежную скидку вместо процентов.

День без времени заканчивается в 23:59:59.999 МСК. Год и часовой пояс для явного времени не угадываются. Невозможная дата, конец раньше начала, противоречивые сроки или один код с разными условиями отменяют полный официальный снимок. При ошибке сохраняются прежний статус и подтверждение. Все возможные форматы сайтов не обещаются: при изменении разметки потребуется адаптация.

## Эксплуатация

- `pnpm db:backup`: SQLite online backup, проверка целостности и таблиц, атомарная публикация готового файла, хранение 14 дней по умолчанию.
- `pnpm db:restore путь/копия.db --server-stopped`: восстановление после остановки приложения/worker с предварительным сохранением текущей базы. Остановку подтверждает оператор.
- `/api/health`: доступность таблицы приложения, HTTP 200/503.
- `deploy/systemd/`: постоянный сервер с встроенным worker, перезапуск при сбое, ежедневный timer копий около 03:15 МСК.
- `deploy/Caddyfile`, `deploy/promospy.env.example` и [инструкция сервера](server-setup.md).

Схема Prisma не менялась. Включённый `db/custom.db` совпадает с исходным файлом по SHA-256: 102 предложения, 136 записей истории, 12 записей очереди. Целостность SQLite проверена; резервная копия этого снимка создана и проверена во время работы. Локальные тестовые копии в архив не включены.

## Что проверено в новом окружении

- **25 тестов прошли**: 16 базовых тестов парсинга/статусов, 4 проверки официальной разметки и ошибок HTTP, 3 новых проверки дат/сумм/будущих акций, 1 проверка online backup/restore с WAL и 1 браузерная проверка обеих официальных карточек.
- Браузерный тест использует реальную сохранённую разметку и изолированный API. Проверены условия, минимальный заказ, фильтр будущих акций, сообщение об ошибке источника и мобильная ширина 390 px. Ошибок JavaScript страницы нет. Это не живая проверка магазинов и не проверка очереди с базой.
- Полный ESLint прошёл.
- TypeScript прошёл.
- Production-сборка и копирование standalone прошли. Для проверки компиляции локально сгенерирован Prisma Client без движка (`--no-engine`), встроенный worker отключён. Эти временные зависимости и сборка не включены в поставку. На целевой машине нужен обычный `pnpm db:generate` с загрузкой штатного движка.
- Сервер запущен: главная вернула HTTP 200. Health вернул ожидаемый 503, поскольку нативный движок Prisma в окружении отсутствует. Полноценная работа приложения с базой через Prisma в этом запуске не подтверждена.

## Что остаётся непроверенным или незавершённым

Сетевая политика нового окружения разрешает серверы пакетов, но блокирует `binaries.prisma.sh`, `vkusvill.ru` и `promo.magnit.ru`. Проверка curl получила **403 на CONNECT от прокси окружения**, а не ответ магазина. Реальные вызовы обоих сборщиков вернули `complete: false`, `fetch failed`, без кодов. Ошибка не использовалась как доказательство исчезновения публикаций и не записывалась в исходный снимок базы.

Поэтому полный набор из **40** unit/integration-тестов с Prisma, `test:smoke`, живое обновление ВкусВилла/Магнита через очередь и восстановление очереди после рестарта нужно повторить после разрешения сети и штатной генерации Prisma. Предыдущие 36 тестов и живые обновления описаны в старой памятке и не выдаются за новые результаты.

Постоянный внешний сервер и отдельное хранилище копий не предоставлены: подготовлены конфигурации и команды, deployment и внешнее резервирование не выполнены. Тануки остаётся заблокированным нерешённым источником. Остальные магазины не подключались без доступа к проверяемым официальным публикациям.

## Как продолжить проверку

После разрешения сети, из корня распакованного проекта:

```sh
pnpm install --frozen-lockfile
# Создать .env из .env.example
pnpm db:generate
pnpm exec playwright install chromium
pnpm test
pnpm typecheck
pnpm lint
pnpm build
pnpm test:smoke
pnpm test:ui
# При остановленном встроенном worker, чтобы он не занимал общую аренду:
node --env-file=.env --import ./scripts/register-ts.mjs scripts/refresh-official.ts 54 201
pnpm start
```

На сервере после переноса использовать абсолютный `DATABASE_URL`, systemd и каталог данных на постоянном диске. Пример штатного запуска и проверки после рестарта — в инструкции сервера.
