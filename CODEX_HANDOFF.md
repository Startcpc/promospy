# PromoSpy 0.11.1

Прочитать docs/release-0.11.1.md и NEXT_AGENT_TASK.md. Пользователь просил работающий поиск и проверку среды. Источники только общедоступные, без входа, обхода CAPTCHA, платных прокси и обязательных API-ключей. Не загружать тестовые коды в рабочие данные.

В этой cloud-среде настоящий HTTP работает через унаследованный прокси с TLS. Node 24.22.1, pnpm 11.25.0, Python 3.12.14, Chromium /usr/bin/chromium. Старое утверждение «живой поиск прочитал 0 страниц из-за сетевой политики» к этой проверке не относится.

Проверены 20 каталогов / 61 адрес: 52 загружены, 9 ошибок (5 robots, 2 HTTP 403, 2 HTTP 404); дополнительно 6 официальных адресов. Добавлен узкий адаптер GetCashback: полные .promo-num, заголовки p, сроки .remain, архив .expired; блок div.coupon-title «Похожие купоны» отсекается. Маски и баннеры не извлекаются. Каталог URL не расширялся непроверенными адресами.

Финальный настоящий браузерный поиск через production API: Burger King 7 страниц / 1 неистёкшее предложение; ВкусВилл 11 / 22; Магнит 25 / 27. Это не проверка применения в корзине. Проверены очередь, обновление с пропуском приостановленных адресов и избранное после reload; 0 browser errors. /api/health — 0.11.1 / ENGINE_VERSION=6. Подробности и числа, включая архив, в release notes.

Команды: pnpm test:live 5 54 201 (ошибка при отсутствии неистёкших предложений); pnpm audit:sources [ID...] (тела документов/robots, HTTP, final URL, время и summary.json в work/source-audit-<время>/). Диагностика не пишет в кеш приложения. Сырые файлы в игнорируемом work/, синтетическая регрессионная фикстура — tests/fixtures/getcashback-public.html.

Проверки завершились успешно: 242 JS, 9 Chromium, 12 Python, 2 SQLite, 22 сценария поиска компаний; lint, типы, production-сборка. db/custom.db и prisma/schema.prisma сохранены без изменений. Не выдавать Linux-проверки за нативные Windows/macOS/Safari.
