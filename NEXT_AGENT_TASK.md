# Следующему агенту — приёмка PromoSpy 0.10.3

Прочитать CODEX_HANDOFF.md и docs/release-0.10.3.md, проверить актуальный main и CI.

1. Сначала сверить реальную сборку пользователя: в «Подробнее об обновлении» и /api/health должна быть версия 0.10.3. Он запускает клон в VS Code; прежний лог содержал текст старого интерфейса. Обновление: остановить процесс, git pull --ff-only origin main, python3 start.py. При ручном pnpm start обязательна новая pnpm build. Не удалять кеш/избранное и не применять force/reset.
2. В доступной runtime-сети проверить Burger King (pnpm test:live 5), затем ВкусВилл и Магнит. Сохранить настоящий HTML, URL, HTTP и условия. Официальный 403 или challenge не объявлять исправленным без успешного чтения. Пикабу использует /shops/burgerkingrus. Для Burger King добавлены публичные getcashback и promokod.vbr, но открытые рабочие коды без наблюдения не гарантируются.
3. Различать ответ robots.txt и доступ к конкретному документу: unavailable robots 4xx обрабатывается по RFC 9309, но сама закрытая страница по-прежнему не читается. 429, сетевые ошибки, 5xx и явный Disallow остаются ограничениями. Не заменять это авторизацией, платными прокси или обходом CAPTCHA.
4. Проверить на машине пользователя получение результатов и повторное обновление. Изолированный сценарий браузера уже воспроизводит 401 robots + 403/404/challenge других источников и успешную публичную альтернативу; это синтетический тест, не живые промокоды. Гонка старых данных со статусом idle также имеет воспроизведение и исправление.
5. Остальные источники расширять по одному. Сохранять точного владельца, сроки, лимиты и независимые кампании одного кода. Для постоянного сервера и физических macOS 12/Safari нужны предоставленные устройства/доступ; не заявлять такую приёмку по одному CI.

После изменений: pnpm check (214 JS, 9 браузерных, 12 Python и данные/сборка), затем живой прогон отдельно. Сохранить db/custom.db и Prisma-схему, обновить отчёт и обычный push.
