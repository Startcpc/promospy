## Что действительно проверено

На этапе 0.4.0 прошли 28 тестов: 26 доступных unit-проверок и 2 браузерных сценария (официальные карточки и полный пользовательский цикл избранного). В браузерных сценариях ответы API изолированы; localStorage, переходы, синхронизация вкладок и мобильный интерфейс настоящие. Полный ESLint, TypeScript и production-компиляция прошли.

Для компиляции временно использовался локально сгенерированный Prisma Client `--no-engine`, поскольку загрузка штатного движка блокировалась. Эти зависимости и сборка не входят в репозиторий. На новой машине выполнить обычный `pnpm db:generate`. Не выдавать ту компиляцию за проверенный запуск приложения с SQLite через Prisma: сервер отдавал главную с HTTP 200, а health — 503 без движка.

## Приоритет 1 — полноценная проверка в новом окружении

1. Проверить доступ к `binaries.prisma.sh`, `vkusvill.ru`, `promo.magnit.ru` и серверам загрузки Chromium. В последнем окружении прокси возвращал 403 на CONNECT; это отказ политики окружения, а не ответ магазина. Не обходить сетевую политику; при необходимости запросить её настройку.
2. Установить зависимости по lock-файлу, создать `.env` из `.env.example`, выполнить штатный `pnpm db:generate`. Не использовать `db:reset` и не перезаписывать заполненную базу.
3. Выполнить `pnpm test`, `pnpm typecheck`, `pnpm lint`, `pnpm build`, `pnpm test:smoke`, `pnpm test:ui`.
4. После штатной генерации Prisma проверить новый API избранного с реальной базой: получение сохранённых, давно истёкших и скрытых из каталога предложений, missingIds и Cache-Control: no-store. Проверки добавлены в `tests/smoke.mjs`, но нативный запуск заблокирован текущим окружением.
5. Обновить 54/201 через `scripts/refresh-official.ts`, пока встроенный worker остановлен, затем проверить автоматический цикл при `pnpm start`. Не запускать два независимых сборщика, конкурирующих за общую аренду.
6. Проверить повторное обновление, сетевую ошибку, неизменность даты успешного подтверждения при сбое, исчезновение и возвращение кода, будущие акции и истечение срока. Использовать сохранённые фрагменты разметки для контролируемых сценариев; не объявлять их живыми проверками.
7. Перезапустить сервер с той же постоянной базой; проверить сохранность истории и восстановление незавершённого задания после истечения аренды.

## Приоритет 2 — постоянный сервер и копии

Внешний сервер не развёрнут. В репозитории находится только комплект установки.

После получения целевого сервера и домена:

- адаптировать `deploy/systemd/*`, `deploy/Caddyfile`, `deploy/promospy.env.example`;
- разместить базу на постоянном локальном диске, использовать абсолютный DATABASE_URL;
- запустить один встроенный worker, проверить health, журнал и период обновления;
- включить timer резервных копий и проверить восстановление на отдельной тестовой базе;
- настроить отдельное внешнее хранилище готовых копий и наблюдение за сбоями;
- проверить приложение и очередь после реального рестарта.

Не заменять рабочую базу включённым снимком при обновлении. Не коммитить `.env`, ключи, рабочие копии базы, логи, node_modules и .next. Для нескольких хостов нужна подходящая общая СУБД, а не отдельные SQLite-файлы.

## Приоритет 3 — следующие магазины по одному

Тануки остаётся нерешённым: QRATOR блокировал самостоятельный сбор. Не повторять без новых оснований прежние неудачные обходы; нужен согласованный источник/доступ или отдельная проверка на целевом сервере. Наличие первоначальных кодов в базе не доказывает автономный сбор.

Следующий магазин подключать после реального изучения доступного официального источника. Сначала адрес и разметка, затем отдельный адаптер и фикстуры, тест полного/частичного снимка, интеграция с очередью и только после этого живая проверка. Исправленный URL Burger King сам по себе не является подключённым источником.

## Правила, которые необходимо сохранить

- `official` означает публикацию на официальном источнике; `verified` — отдельную успешную проверку конкретной корзины.
- При 401/403, таймауте, сетевой ошибке или нераспознанной разметке сохранять последнее успешное официальное подтверждение и его дату.
- Снимать официальный статус при доказанном исчезновении из полностью прочитанного списка либо известном истечении срока. Пустая непонятная страница не доказывает исчезновение всех кодов.
- Не добавлять шестичасовой срок жизни для `official`; такое ограничение относится к подтверждениям корзины.
- Не выдумывать коды, даты, условия, регион и факт успешного сбора. Сохранять регистр и кириллицу.
- Не оформлять покупки и не выполнять вход в аккаунты без отдельной необходимости и разрешения.
- Сохранять текущий интерфейс и историю. Перед изменением схемы делать резервную копию.
