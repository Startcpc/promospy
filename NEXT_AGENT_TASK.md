# Следующему агенту — PromoSpy 0.11.1

Прочитать CODEX_HANDOFF.md и docs/release-0.11.1.md. Живой поиск в доступной сети уже подтверждён, не повторять прежний вывод о 0 страницах. Пользователь выбрал только открытые источники без входа и обхода блокировок.

1. Проверить актуальный main и /api/health. Обновление клона: остановить сервер, git pull --ff-only origin main, python3 start.py. Не удалять кеш, избранное, SQLite, Prisma или резервные копии.
2. Для нового дефекта сначала воспроизвести его: pnpm test:live 5 54 201; pnpm audit:sources [ID...]. Вторая команда сохраняет настоящий HTTP, конечный URL, robots, тела и время в work/source-audit-<UTC>/, отдельно от кеша.
3. Оставшиеся наблюдения: Fontanka Магнит и часть Promocodex имеют неполные/неоднозначные даты; Okodo Магнит даёт короткие даты без года в карточке; Технопанорама и ПромКод показывают хвосты/маски. Не угадывать код или срок. Полный год из контекста требует однозначной связи с той же кампанией.
4. Не возвращать promokodus без новых подтверждений публичного доступа. Mail.ru и 7days не удалось проверить robots; Промокоди.net/Промокодофф дали 403; Okodo ВкусВилл и КП Яндекс Маркет — 404. Наличие в индексе не доказывает доступность. Новые URL добавлять после реального наблюдения, не конструировать неизвестные slug.
5. При изменении парсера сохранять раздельность магазинов и кампаний, даты, архив, минимум, регион и канал. У GetCashback рекомендации имеют ту же разметку и начинаются с div.coupon-title «Похожие купоны». Не переносить тестовые коды в рабочие данные.
6. После изменений выполнить затронутые проверки; полный набор — PROMO_TEST_CHROMIUM_EXECUTABLE=/usr/bin/chromium pnpm check. Сейчас 242 JS, 9 браузерных, 12 Python, 2 SQLite, 22 проверки поиска компаний. Физические macOS 12/Safari и Windows проверять на целевых устройствах.

Описывать фактические результаты отдельно от контролируемых тестов. Найденное не считать применённым в корзине; аккаунты и заказы без отдельного поручения не использовать. Делать обычный коммит и push без force/reset.
